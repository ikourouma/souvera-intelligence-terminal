# Souvera Data Source & Ingestion Strategy v1.0

**Owner:** Afronovation, Inc.
**Product:** Souvera Intelligence Terminal (SIT)
**Document Type:** Canonical Data Operations + Ingestion Strategy
**Status:** Final documentation draft for project folder

---

## 1. Purpose

This document defines how Souvera acquires, validates, normalizes, stores, refreshes, and serves data.

It governs:

* approved data sources
* API access links
* ingestion pipelines
* source priority
* failover
* transformation rules
* data freshness
* validation
* source attribution
* tier-based access
* AfDEC-lite consumption

Souvera does not exist without this layer. The data engine is the product foundation.

---

## 2. Core data principle

> Souvera does not merely display data. Souvera transforms fragmented external data into decision-grade intelligence.

All external data must flow through the Souvera ingestion and normalization layer before it reaches any user interface, API, report, or AfDEC integration.

---

## 3. Data architecture overview

```text
Approved External Sources
        ↓
Provider Adapters
        ↓
Raw Payload Archive
        ↓
Validation Layer
        ↓
Normalization Layer
        ↓
Souvera Supabase Database
        ↓
Signal Engine
        ↓
Entitlement Filter
        ↓
Terminal UI / Enterprise API / AfDEC Lite
```

---

## 4. Non-negotiable rules

1. No frontend calls external APIs directly.
2. No unregistered source enters production.
3. No data point is displayed without source attribution.
4. No premium data is sent to unauthorized users.
5. No AfDEC route receives full Souvera data.
6. All ingestion jobs must log success, failure, record count, and source health.
7. Licensed or restricted data must be tier-gated and legally reviewed before production use.

## 6. Launch data source stack

The World Bank Indicators API is the public macro backbone because it provides programmatic access to nearly 16,000 time-series indicators across 45+ databases. ([World Bank Data Help Desk][1]) IMF data should be used for forecast and macro validation because it is distributed through SDMX-based data APIs and workflows. ([teal-insights.github.io][2]) UN Comtrade is the primary trade source because it aggregates detailed global annual and monthly trade statistics by product and trading partner. ([comtrade.un.org][3]) GDELT is the primary news-signal source because it provides live realtime JSON APIs such as DOC, GEO, and TV for global media analysis. ([GDELT Project][4])

## 8. Ingestion adapter architecture

All providers should be implemented as isolated adapters.

```text
/services/ingestion
  restcountries.ts
  worldbank.ts
  imf.ts
  oecd.ts
  comtrade.ts
  oxr.ts
  gdelt.ts
  newsapi.ts
  afdb.ts
  tradingeconomics.ts
  iea.ts
```

Each adapter must expose:

```ts
type IngestionResult<T> = {
  sourceKey: string
  jobId: string
  success: boolean
  recordsProcessed: number
  recordsFailed: number
  fetchedAt: string
  data?: T[]
  error?: string
}
```

---

## 9. Ingestion process standard

Every ingestion job must follow this order:

1. create ingestion job record
2. fetch provider payload
3. archive raw payload
4. validate response
5. transform provider payload
6. normalize to Souvera schema
7. upsert into target tables
8. update source health
9. compute derived signals if applicable
10. close ingestion job

---

## 12. Normalization standard

Every metric observation must normalize into:

```ts
type SouveraObservation = {
  countryIso3: string
  indicatorKey: string
  periodDate: string
  periodType: "daily" | "monthly" | "quarterly" | "annual"
  valueNumeric?: number
  valueText?: string
  sourceKey: string
  sourceSeriesKey?: string
  isForecast: boolean
  isEstimate: boolean
  qualityScore: number
  fetchedAt: string
  publishedAt?: string
}
```

## 15. News signal transformation

GDELT and NewsAPI should not be dumped raw into the terminal. They should be summarized into signal fields:

```ts
type NewsSignal = {
  countryIso3: string
  signalDate: string
  headlineCount: number
  riskIntensity: number
  opportunityIntensity: number
  sentimentScore: number
  topHeadlines: Array<{
    title: string
    source?: string
    url?: string
    publishedAt?: string
  }>
  sourceMix: Record<string, number>
}
```

UI must show a signal, not a noisy news feed.

---

## 16. Trade snapshot transformation

UN Comtrade should be transformed into summary snapshots:

```ts
type TradeSnapshot = {
  countryIso3: string
  year: number
  topExports: Array<{
    label: string
    valueUsd?: number
    sharePct?: number
  }>
  topImports: Array<{
    label: string
    valueUsd?: number
    sharePct?: number
  }>
  topTradePartners: Array<{
    country: string
    valueUsd?: number
    relationship?: "export" | "import" | "both"
  }>
}
```

Avoid exposing raw commodity-level complexity in v1.

## 17. Validation rules

### Required validation

* valid country ISO3
* known indicator key
* valid period date
* source exists in registry
* value is numeric where expected
* data point is not absurdly out of range
* source timestamp is recorded

### Reject or quarantine when:

* country cannot be mapped
* source is not approved
* payload shape is invalid
* value is corrupt or non-parsable
* legal status is not approved for production

## 18. Quality scoring

Each observation should receive a quality score from 0 to 1.

Suggested scoring:

| Factor                    | Weight |
| ------------------------- | -----: |
| source reliability        |   0.35 |
| freshness                 |   0.25 |
| completeness              |   0.20 |
| transformation confidence |   0.20 |

Example:

```ts
qualityScore =
  sourceReliability * 0.35 +
  freshnessScore * 0.25 +
  completenessScore * 0.20 +
  transformConfidence * 0.20
```

## 20. Source health policy

| Status   | Meaning                   | Action                   |
| -------- | ------------------------- | ------------------------ |
| Healthy  | last job succeeded        | continue                 |
| Degraded | repeated failure or stale | activate fallback        |
| Down     | unusable source           | use cached/fallback data |
| Paused   | manually disabled         | no ingestion             |
| Retired  | removed from production   | no ingestion             |

---

## 21. Entitlement-aware serving

The ingestion system stores the full normalized dataset. The API layer decides what a user may receive.

| Tier           | Data access behavior                                  |
| -------------- | ----------------------------------------------------- |
| Public         | country identity, headline macro, teaser sectors      |
| Explorer       | public + limited comparison                           |
| Professional   | full macro, FX, sectors, signals                      |
| Business       | forecasts, trade, reports                             |
| Investor       | investor memos, deeper signal logic, expanded compare |
| Institutional  | API, export, org workspace, audit                     |
| Platform Admin | full internal access                                  |

No frontend-only filtering is allowed.

---

## 22. AfDEC-lite serving model

AfDEC consumes only:

* `/api/v1/countries-lite`
* `/api/v1/country-lite`
* `/api/v1/compare-lite`
* `/api/v1/insight-teaser`

AfDEC must not receive:

* raw time series
* trade datasets
* investor memos
* export endpoints
* source payload archives
* full signal logic
* direct Supabase credentials

## 26. Error handling standard

| Error             | System behavior                    |
| ----------------- | ---------------------------------- |
| API timeout       | retry with backoff                 |
| auth failure      | mark source degraded + alert admin |
| schema change     | fail safely + archive payload      |
| partial data      | ingest valid rows, flag partial    |
| provider down     | use fallback / cached              |
| legal restriction | suppress field                     |
