# Souvera API Binding Map v1.1

**Owner:** Afronovation, Inc.
**Product:** Souvera Intelligence Terminal
**Purpose:** Define how Souvera APIs, external data sources, Supabase tables, entitlements, AfDEC-lite endpoints, and UI components connect.

---

## 1. Core principle

Souvera is the intelligence source of truth.

AfDEC, partners, dashboards, and enterprise clients consume Souvera through controlled APIs only.

```text
External Data Sources
        ↓
Souvera Ingestion Adapters
        ↓
Souvera Supabase Intelligence Database
        ↓
Souvera API Layer
        ↓
Souvera Terminal / AfDEC Lite / Enterprise Clients
```

---

# 4. Public / AfDEC-lite API bindings

AfDEC should only consume lite endpoints.

## 4.1 `GET /api/v1/country-lite`

**Purpose:** Return controlled teaser data for one country.

### Query

```http
GET /api/v1/country-lite?iso3=ZMB
```

### Reads from

* `souvera_country_lite_v`
* `souvera_country_sectors`
* `souvera_country_news_signals`

### Returns

```ts
type CountryLiteResponse = {
  country: {
    iso2: string
    iso3: string
    name: string
    region: string
    subregion?: string
    capital?: string
    currencyCode?: string
    flagUrl?: string
  }
  metrics: {
    gdpCurrentUsd?: number
    gdpGrowthPct?: number
    populationTotal?: number
  }
  signal: {
    level?: "high_growth" | "emerging" | "stable" | "watchlist" | "risk_elevated"
    investmentScore?: number
    confidenceScore?: number
  }
  sectors: Array<{
    label: string
    teaser?: string
  }>
  teaser: {
    afdecTeaser?: string
  }
  freshness: {
    updatedAt?: string
  }
}
```

### Access

* Public
* AfDEC
* Explorer
* Any higher tier

### Not allowed

* FDI detail
* full risk narrative
* full opportunity thesis
* reports
* exports
* raw source payloads

---

## 4.2 `GET /api/v1/compare-lite`

**Purpose:** Allow limited public / AfDEC comparison.

### Query

```http
GET /api/v1/compare-lite?countries=ZMB,AGO
```

### Reads from

* `souvera_country_lite_v`

### Returns

* country identity
* GDP
* population
* GDP growth
* signal label

### Access

* Public / AfDEC allowed

### Limits

* max 2 countries
* no historical charts
* no trade comparison
* no risk comparison

---

## 4.3 `GET /api/v1/insight-teaser`

**Purpose:** Return one curated teaser insight for a country or region.

### Query

```http
GET /api/v1/insight-teaser?iso3=ZMB
```

### Reads from

* `souvera_country_profiles.afdec_teaser_md`
* `souvera_country_signal_scores`
* selected latest observations

### Returns

```ts
{
  country: "Zambia",
  teaser: "Zambia is positioned as an emerging market signal...",
  signal: "emerging",
  updatedAt: "2026-04-24T00:00:00Z"
}
```

# 10. Entitlement middleware binding

Every Souvera route should use a server-side access resolver.

```ts
type SouveraAccessContext = {
  userId?: string
  organizationId?: string
  planId: "public" | "explorer" | "professional" | "business" | "investor" | "institutional" | "platform_admin"
  entitlements: string[]
  role?: "viewer" | "analyst" | "strategist" | "executive" | "org_admin" | "platform_admin"
}
```

## Required logic

* resolve user
* resolve organization
* resolve highest plan rank
* resolve entitlements
* filter response server-side
* audit premium and enterprise access

# 11. Response metadata standard

Every API response should include:

```ts
meta: {
  product: "souvera"
  owner: "Afronovation, Inc."
  accessTier: string
  generatedAt: string
  freshness: {
    macro?: string
    forecast?: string
    fx?: string
    news?: string
    trade?: string
  }
  sources: Array<{
    key: string
    name: string
    asOf?: string
  }>
}
```

This is mandatory for credibility.

# 12. Error and degradation binding

| Condition              | API behavior                       | UI behavior                        |
| ---------------------- | ---------------------------------- | ---------------------------------- |
| Source down            | return cached data + degraded flag | show stale badge                   |
| User lacks entitlement | return locked module metadata      | show locked card                   |
| No data available      | return null field + reason         | show unavailable state             |
| API key invalid        | 401                                | enterprise error                   |
| Rate limit exceeded    | 429                                | retry / contact admin              |
| Legal restriction      | suppress restricted field          | show “not available for this plan” |

# 13. AfDEC-lite contract

AfDEC must never receive full Souvera payloads.

## Allowed

* `country-lite`
* `compare-lite`
* `insight-teaser`

## Not allowed

* `/api/v1/country`
* `/api/v1/country/series`
* `/api/v1/trade`
* `/api/v1/reports`
* `/api/v1/enterprise/export`
* direct Supabase access

## AfDEC display rule

AfDEC must show:

* “Powered by Souvera Terminal”
* “Engineered by Afronovation, Inc.”
* optional “Endorsed by AfDEC” only where appropriate

# 15. Final binding rule

The API layer is the contract.

Souvera’s database may evolve, providers may change, and UI may improve, but **external consumers and AfDEC must only depend on the versioned Souvera API contract**.

Recommended next artifact: **Souvera Route-by-Route Build Spec v1.1**, updated for the standalone Souvera platform and AfDEC-lite integration.
