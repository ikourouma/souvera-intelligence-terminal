# Souvera Route-by-Route Build Spec v1.1

**Owner:** Afronovation, Inc.
**Product:** Souvera Intelligence Terminal
**Purpose:** define every core route, page objective, data source, API dependency, access behavior, UI modules, lock states, and integration boundaries.

---

## 1. Build principle

Souvera is the source of truth. AfDEC is a governed lite consumer.

No Souvera route should depend on AfDEC.
AfDEC should depend only on versioned Souvera lite APIs.

---

# 2. Route groups

| Route Group        | Purpose                                       |
| ------------------ | --------------------------------------------- |
| Public Marketing   | Position Souvera and capture enterprise leads |
| Public Teaser      | Limited intelligence preview                  |
| Auth / Onboarding  | Invite-only access, org setup                 |
| Terminal Workspace | Full intelligence product                     |
| Reports            | Downloadable intelligence assets              |
| Enterprise / API   | API clients, usage, exports                   |
| Admin Console      | Source, ingestion, editorial, governance      |
| AfDEC Integration  | Lite endpoints consumed by AfDEC              |

# 10. AfDEC integration routes

AfDEC should call only these Souvera endpoints:

| AfDEC Need            | Souvera Endpoint         |
| --------------------- | ------------------------ |
| Africa map teaser     | `/api/v1/countries-lite` |
| Country drawer teaser | `/api/v1/country-lite`   |
| Compare teaser        | `/api/v1/compare-lite`   |
| Insight block         | `/api/v1/insight-teaser` |

AfDEC should not:

* access Souvera Supabase directly
* store full Souvera intelligence
* expose Souvera premium fields
* duplicate signal logic

# 11. Lock states by route

| Route                      | Locked modules                               |
| -------------------------- | -------------------------------------------- |
| `/intelligence`            | full panel, trade, reports, compare          |

| `/terminal/sectors`        | sector thesis                                |

| `/terminal/api`            | full API creation                            |
| `/terminal/exports`        | all exports unless institutional             |

# 12. Analytics events

Every major route should emit product analytics events.

| Event                     | Trigger                     |
| ------------------------- | --------------------------- |
| `public_teaser_viewed`    | user visits `/intelligence` |
| `country_lite_opened`     | country drawer opened       |
| `locked_module_clicked`   | locked module selected      |
| `request_access_clicked`  | CTA clicked                 |
| `terminal_country_opened` | full country page opened    |
| `compare_started`         | compare route used          |
| `report_downloaded`       | report downloaded           |
| `api_key_created`         | enterprise API key created  |
| `ingestion_job_failed`    | admin ingestion failure     |

# 14. Final route rule

Each route must answer one question:

* Public routes: “Why should I care?”
* Teaser routes: “What can Souvera show me?”
* Terminal routes: “What decision can I make?”
* Enterprise routes: “How do I operationalize this?”
* Admin routes: “Can Afronovation trust the system?”
